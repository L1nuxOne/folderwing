Subject: Clarification: redistribution of PDFium /MD output under VS 2022 Build Tools OSS dependency terms

Hello C++ team,

I am preparing Folderwing, a personal Windows application whose own source is MIT,
for public source and binary distribution. Its PDF preview uses third-party
PDFium, built from BSD-licensed source with the accompanying component notices.

The controlled build uses Chromium Clang/LLD, release MSVC libraries from toolset
14.44.35207, and Windows SDK 10.0.26100.0. Microsoft payloads were obtained from
the official Visual Studio 2022 manifest into a portable build directory under
the Build Tools OSS-dependency permission, not from an installed Community IDE.
The changes to PDFium are limited to build/interface configuration.

All translation units use /MD. The resulting pdfium.dll imports the Windows UCRT,
VCRUNTIME140.dll and VCRUNTIME140_1.dll. Its map also shows 30 release startup/support
objects from msvcrt.lib and one from vcruntime.lib, including CRT entry-point/TLS
initialization and security-cookie support. No debug libraries are used.

We intend to distribute only the application/PDFium binaries and required notices.
The VC runtime will be an external prerequisite installed using Microsoft's
official installer. We will not distribute Microsoft's toolchain, CRT sources,
loose Microsoft .lib files, runtime DLLs, or runtime installer.

Could you confirm the applicable licensing basis and requirements?

   package carry, and what agreement, if any, must external users/distributors

   granted by the MIT/BSD and other open-source component licenses.
